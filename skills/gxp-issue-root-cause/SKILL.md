# GXP 业务根因分析 - Codex

处理用户当前提供的问题，不把调用本技能理解成创建或修改技能文件。

## 先加载共同规则

完整读取本技能目录的 [references/business-rules.md](references/business-rules.md)。以该文件为业务判断和输出依据；不要只凭技能描述作答。最终默认只输出每个问题的“根本原因、解决方法、影响范围”。

## Codex 适配

- 用户可用 `$gxp-issue-root-cause` 调用。使用当前用户消息和会话里已经确认的业务事实；纠正信息优先，之前的猜测不是证据。
- 仅整理已有材料时，读取共同规则后直接处理。没有处理记录、但要求分析问题时，按规则主动只读排查。
- 实际排查先从本次可用技能目录定位 `gxp-lowcode-readonly:gxp-lowcode-debug`，读取其正文及任务所需引用文件。不把插件命名空间当文件路径，不固定缓存版本。
- 使用本次实际暴露的 `gxp-lowcode-readonly` MCP 工具；前缀可能被客户端规范化，不手写或猜测工具参数。仅在需要时发现对应工具，不把“已发现”说成“查询成功”。
- 原技能提供查证流程，本技能决定业务回填的表达格式。用户只要三项结论时不附原技能的技术定位报告；必须保留不确定性和事实限定。
- 不执行业务修改、草稿保存、发布、源码修改或写入类 MCP。读不到必要规则或工具不可用时，说清证据缺口，不能绕过限制或凭经验补原因。
- 每条最终业务断言都应能对应本次读取的证据或用户材料。工具返回截断时先按原技能规则补读；当前版本的静态检查不能证明历史错误或运行验收通过。

修改技能或进行验收时才读取 [references/acceptance-cases.md](references/acceptance-cases.md)，不要把测试场景带入普通业务排查。
