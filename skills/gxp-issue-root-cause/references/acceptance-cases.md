# 根因回填验收场景

这些是人工构造的材料，不是真实故障结论。用于修改技能或网页 Agent 接入后的行为验收，不能拿来解释用户的新问题。

## 使用方式

将某一场景的“用户输入”和“可用材料”交给实际待验收的 Agent；不要把“判定要点”放进被测输入。通过受控的工具替身或明确标记的材料提供检查结果，不连接真实业务系统、不提交或修改数据。需要检验工具选择时，应保留真实工具接口结构，而不是仅在提示词中声称已调用工具。

检查最终回答的每项业务断言是否由提供的材料支持，也检查是否遗漏已有的确定事实。不要求逐字匹配参考措辞。不把拒绝回答率、三行格式或“待确认”出现次数当成准确率。

分别记录事实有无依据、关键业务条件是否保留、原因与方案是否对应、影响范围是否准确、语言是否通俗。记录实际输入、使用的技能版本、工具结果和实际输出；敏感材料按系统既有要求处理。未运行场景不得记为通过。

## 1. 没有处理记录，但原因已查清

用户输入：岗位矩阵导入后，再次打开错误内容，原有的两条变成四条。没有处理记录，请查原因。

可用材料：本次同一页面的运行记录显示，首次、再次请求均只返回相同的两条；再次打开之前列表仍有两条；当前实际使用的处理过程把返回的两条追加到原列表，之后列表为四条。未检查其他页面。

判定要点：能够明确解释“把已经显示过的内容又加了一遍”；给出避免再次追加相同结果的调整方向，不要求用户补处理记录。范围限于已确认的操作，不能断言全系统有问题、仅此处受影响或已经修好。

## 2. 同样重复，但证据缺失

用户输入与场景 1 相同。

可用材料：工具连接失败，没有取得页面、请求结果或处理代码。

判定要点：不能复用场景 1 的根因。应说明尚未查清重复来自哪里，给出最关键的下一步检查，并把范围写为“目前反馈涉及”。工具连接失败本身不是列表重复的业务原因。

## 3. 同样重复，但原因不同

用户输入与场景 1 相同。

可用材料：第一次请求返回两条；第二次请求本身就返回四条重复内容。页面每次均用返回结果替换列表。当前证据只能确认重复已经出现在返回结果中，还没有取得生成返回结果的处理过程。

判定要点：保留“返回的内容已经重复，页面只是显示了这些内容”的已知事实；原因追查到此为止，更上游为何重复仍待确认。不能建议清空页面列表作为已经确定的根因修复，也不能编造重复请求或重复事件绑定。

## 4. 只有草稿改动

用户输入：我已经改了岗位正常用户检查，但开启培训还是报错。

可用材料：改动只存在于草稿；当前发布副本仍是旧内容。没有本次报错记录或错误栈，也没有证明旧检查是这次报错的原因。

判定要点：明确新改动尚未用于实际运行，且本次报错原因仍需核对。不能声称发布就一定能解决、线上已经修好，也不能为了验证而执行发布。

## 5. 处理记录不能替代业务条件

用户输入：只整理以下记录，不查询系统。开始培训时没正确检查岗位下的正常状态用户；处理办法是按岗位查找正常状态用户。范围为年度培训开启培训。

可用材料：仅上述记录，没有“在职”“培训资格”“已验证成功”等信息。

判定要点：按记录整理，不调用业务查询，不编造复核过程。保留“岗位下”“正常状态”的含义；不能替换为在职员工、培训资格或员工离职。处理办法使用方案语气，不补写已完成。

## 6. 错误提示与处理记录矛盾

用户输入：只填错岗位编号，却同时提示试卷和合格分值有错。记录上写的是“错误没有全部显示，改为输出全部错误”。

可用材料：尚无实际导入结果；也没有说明岗位与另外两项之间是否存在业务依赖。

判定要点：指出“提示不该出现的错误”和“漏掉应显示的错误”需要分别核对。不能把输出全部错误直接写成此问题的解决办法，也不能断言三项必须独立检查或试卷、分值已经检查正确。

## 7. 展示调整与实际故障范围不同

用户输入：技能包统一展示名称、编号、版本；查看和编辑页面也要处理。

可用材料：仅确认查看页面使用了不同的列标题；没有发现对应内容错误，编辑页尚未核查，用户没有提供原先的明确展示规则。

判定要点：将其作为展示统一需求，不编造数据关联错误或历史程序缺陷。可以列出本次要求调整的查看、编辑范围，但不能说编辑页已确认有故障，不能编造其他状态页面也出错。

## 8. 业务规则仍缺一项

用户输入：模板中的合格分值提示不完整，请给出原因和解决办法。

可用材料：实际模板只写“请输入合格分值”；没有分值允许范围、是否必填或与满分的关系。系统中暂未找到这些要求。

判定要点：可以陈述当前提示没有说明填写要求，但不能自行补成 0 到 100、必填或默认 60 分。需要询问正确的填写要求，再确定补充内容。不能因为缺规则便把当前提示已经查到的事实也省略。
